# 架構說明

## 誰跟誰在溝通

瀏覽器先從 GitHub Pages 下載靜態網頁；之後所有聊天資料都由瀏覽器直接跟 Supabase 往來。GitHub Pages 只能放靜態檔案，不能放秘密，所以**所有規則的把關都做在 Supabase 的資料庫**，前端的檢查只是讓使用者即時看到原因。

## 程式分三層

| 檔案 | 責任 |
|---|---|
| `src/rules.ts` | 純規則：代號與內容清理、長度檢查、收到資料的格式驗證（`parsePost`）、錯誤代碼對應說明 |
| `src/room.ts` | 唯一跟 Supabase 說話的地方：匿名登入、`join_room`、訂閱即時訊息與在線人數、讀歷史、送出、斷線重連 |
| `src/main.ts` | 畫面：進入畫面、聊天室、訊息列表。只透過 `Room` 取得資料，不直接碰 Supabase |

## 資料庫（`supabase/schema.sql`）

- `room_members`：每個匿名身分一個固定的 3 碼編號與名稱。
- `room_posts`：貼文。前端只能寫入 `id` 與 `body`；發言者、名稱、時間由 trigger 填；沒有任何人能改或刪。
- `join_room(p_alias)`：清理並檢查代號（1～12 字），回傳「代號#編號」。
- `room_posts_guard` trigger：內容清理、1～500 字、每人 10 秒最多 5 則且間隔至少 0.5 秒。
- Realtime：新貼文即時推送；在線人數用 Presence（不用資料表）。

## 安全

- 訊息一律用 `textContent` 顯示，不當 HTML。
- 收到的訊息先檢查欄位格式，不合格丟棄。
- 只使用 Project URL 與 publishable key；不使用、不寫入 secret key 或資料庫密碼。

## 已知限制

- 代號可以重複（編號不同），單看代號可能混淆。
- 訊息永久保存在資料庫，容量長期會增長；畫面一次只載入 50 則。
- 在線人數靠 Presence，直接斷網或當機時要等逾時才會減少。

## 驗證清單

- [ ] 打開網址第一個看到進入畫面，尚未連線
- [ ] 代號空白、超過 12 字：按鈕停用並顯示原因；Enter 也能送出合格的代號
- [ ] 進入後頂部顯示「你是：代號#三碼」；同一個瀏覽器再進入編號不變
- [ ] 兩個不同瀏覽器互傳訊息，1～2 秒內出現，不用重新整理
- [ ] 在線人數隨進出變化；按「離開」後對方人數馬上減少
- [ ] 往上載入更早的訊息、「已經是最早的訊息」、失敗可重試
- [ ] 傳送狀態：傳送中 → 已送出；失敗可重試
- [ ] 快速連發出現「發言太快了」
- [ ] 貼上 `<b>粗體</b>` 原樣顯示為文字
- [ ] 手機寬度沒有橫向捲軸
- [ ] 原始碼與打包結果找不到 secret key
