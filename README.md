# 匿名聊天室 2

一個不用註冊登入的匿名聊天室，所有人在同一個聊天室裡。前端用原生 TypeScript 加 Vite，部署在 GitHub Pages；後端用 Supabase（資料庫、即時推送、在線人數、匿名登入）。

## 進入方式

1. 打開網址，第一個看到的是進入畫面。
2. 在「代號」輸入框輸入代號（去頭尾空白後 1～12 字，不合格時按鈕停用並顯示原因）。
3. 按「進入聊天室」（或在輸入框按 Enter）。

進入後你的名稱是「代號＋#＋3 碼編號」，例如「小明#371」，顯示在頂部的「你是：」。編號由資料庫產生，同一個匿名身分固定不變，無法自己指定。

## 新增功能（在畫面上怎麼看到）

| 功能 | 在畫面上怎麼看到 |
|---|---|
| ① 資料庫強制發言頻率限制（10 秒 5 則、間隔 0.5 秒） | 連續快速送出訊息，超過限制時輸入框上方顯示「發言太快了，請稍等幾秒」，幾秒後消失；該則訊息顯示「傳送失敗」。 |
| ② 伺服器端內容清理（移除隱形字元、連續空行折成一個、去頭尾空白） | 送出含零寬字元、很多空行或頭尾空白的訊息，顯示出來的是清理後的版本。 |
| ③ 匿名登入＋資料庫產生的固定 3 碼編號 | 進入後頂部顯示「你是：小明#371」；同一瀏覽器再進入編號不變，換瀏覽器編號不同，無法自己指定。 |
| ④ 傳送狀態與重試 | 自己的訊息下方依序顯示「傳送中…」→「已送出」；失敗顯示「傳送失敗」和「重試」按鈕，重送用同一個 id，不會重複。 |
| ⑤ 字數計數器 | 輸入框下方即時顯示「0 / 500」，超過 500 字變紅色並停用送出鈕。 |
| ⑥ 載入更早的訊息 | 進入時看到最近 50 則；聊天室累積超過 50 則後，訊息區最上方才會出現「載入更早的訊息」按鈕，按下會再載入 50 則，載完顯示「已經是最早的訊息」，失敗時按鈕變成「載入更早的訊息失敗，按一下重試」。 |
| ⑦ 「正在輸入…」提示（Realtime Broadcast，和所有人即時同步） | 一邊在輸入框打字，另一邊在輸入框上方看到「某某 正在輸入…」；停止約 5 秒或對方送出訊息後消失。 |

## 基本功能

| 功能 | 在畫面上怎麼看到 |
|---|---|
| 即時聊天 | 一邊送出訊息，另一個視窗不用重新整理就出現。 |
| 在線名單與進出提示 | 頂部「N 人在線」，點開是名單（自己標「（你）」）；有人進來或離開時顯示「某某 進來了／離開了」，按「離開」對方人數馬上減少。 |
| 純文字顯示 | 貼上 `<b>粗體</b>` 原樣顯示成文字。 |
| 收到的訊息先驗證格式 | 格式不合（id 非 UUID、名稱非 1–20 字、內容非 1–500 字、時間無法解析）的訊息不顯示，只在 Console 留一行警告。 |
| 斷線重連 | 斷線顯示「重新連線中…」，恢復後補齊訊息；超過 60 秒回到進入畫面。 |
| 展示模式（階段一） | 不設定金鑰時，進入畫面會顯示「展示模式」提示，訊息只存在你的瀏覽器，有機器人發言與進出。 |

## 本機啟動

```
npm install
npm run dev
```

複製 `.env.example` 成 `.env.local`（`VITE_CHAT_MODE=live` 連 Supabase；不設定則是展示模式，不需要金鑰），填入 Project URL 與 publishable key（可公開金鑰）。絕不放 secret key 或資料庫密碼；`.env.local` 不會被 commit。

## 資料庫

不使用 Supabase CLI。到 Supabase 後台：

1. Authentication → Sign In / Providers，打開 **Allow anonymous sign-ins**。
2. SQL Editor → New query，把 `supabase/schema.sql` 的**內容**整份貼上，按 Run。

## 部署

推到 `main` 後，GitHub Actions（`.github/workflows/pages.yml`）自動打包並上架到 GitHub Pages。Project URL 與 publishable key 放在儲存庫 Settings → Secrets and variables → Actions（`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`）。

展示模式（階段一）也能放上 Pages：Actions → Deploy to GitHub Pages → Run workflow，`chat_mode` 選 `demo`（說明見 `docs/architecture.md` 第 4、12 節）。

需求見 `docs/requirements.md`，設計說明見 `docs/architecture.md`。
